# WowDeck 通用 HTML 演示 Skill 设计

目标 Skill：`skill/wowdeck`

## 1. 设计结论

WowDeck 不是一套“高级模板”，而是一套把材料转成适合特定受众、传播任务和交付环境的 HTML 演示方法。

它复用的是稳定运行时、真实性规则和验收门禁，不复用固定故事线、行业隐喻、页数、视觉风格或动效。教学、研究、数据汇报、内部复盘、品牌发布、产品演示和商业提案可以得到完全不同的内容逻辑。

主要产物是浏览器原生 HTML。PPTX、PDF、录屏、视频、离线包、二维码和公网链接都是独立交付物，只有用户明确要求并完成对应验收时，才可声称完成。

## 2. 可复用的生成原则

根据具体沟通任务组合以下原则，不固定页序：

1. 在写 HTML 前，确定受众、希望发生的变化、时间、事实边界和交付环境。
2. 从材料的依赖关系生成内容路径，不从行业名称选择模板。
3. 用一份结构化内容源驱动页面、讲稿、时长、主讲/附录、事实状态与媒体引用。
4. 复用稳定运行时；每个案例重做叙事、视觉语法和真正需要的交互。
5. 媒体按沟通任务选择：真实流程用录屏，精确界面用真实截图或 HTML，状态变化可用确定性动画，生成图片承担氛围和解释而不伪造证据。
6. 结构、浏览器行为、视觉可读性、媒体、打包和外部结果分层验收。
7. 每次验收绑定最终产物身份；产物变化后旧回执自动失效。

以下失败模式需要在方法中预防：配置时长不等于完整彩排；构建脚本与成品分离会失去可复现性；字符串补丁和绝对路径会制造版本漂移；图像模型不适合重绘精确 UI 与中文；“本地可打开”不能证明公网可访问或正式提交成功。

## 3. 五项内部 Strategy Note

生成前只保留五项会改变结果的判断。它是内部工作笔记，不是强迫用户填写的表单；信息足够时应合理推断并标注假设。

1. **Audience / context**：谁看、已有认知、场合、观看距离、是否脱离讲解转发。
2. **Desired shift / communication job**：希望观众学会、理解、相信、决定、感受或采取什么行动。
3. **Central question / route / ending**：演示回答什么核心问题，理解依赖如何展开，以什么行为或认识结束。
4. **Claim / evidence risk**：哪些是事实、推断、模拟、建议和未知；错误陈述的代价与来源要求。
5. **Delivery constraints / optional features**：格式、比例、时长、设备、离线/联网、分享方式，以及是否启用 navigation、presenter、media、dialog。

只有缺失选择会实质改变产物、风险、成本或授权边界时才询问。不要生成四十字段的策略合同，也不要记录“采用/拒绝了哪些模板”的元推理日志。

## 4. 内容逻辑：先画依赖图，再定页序

每个候选内容单元至少回答：观众为什么需要它、理解它依赖什么、它让观众发生什么变化、需要何种证据、适合何种呈现形式。

生成顺序：

1. 列出当前材料能支持的主张、例子、过程、数据、疑问和边界。
2. 建立前置依赖、因果、比较、时间或空间关系。
3. 从 desired shift 反向选择最小必要内容，删除不能推动理解或行动的内容。
4. 把依赖相近的内容组织成章节和页面角色。
5. 设计重点、呼吸、回顾和结尾；不是每页都做高潮。
6. 将技术细节、完整证据、长媒体和问答材料移入附录，前提是主线无需它们也能成立。

教学可以从已有认知到迁移练习，研究可以从问题与缺口到方法、结果和局限，数据汇报可以从口径到观察、驱动因素与不确定性，品牌发布可以从信念与张力到揭晓与记忆锚点。它们只是推理先验，不是固定模板。

同一事实源面向不同受众时，事实不变，但术语、顺序、密度、自解释程度、证据显著度与结尾可以改变。初学者需要直觉与脚手架，专家需要方法与边界，管理层需要影响、权衡、风险和所需支持。

## 5. 视觉与强调

视觉由认知任务、受众、场合、媒介与内容结构共同决定，而不是由行业名称直接映射主题。

- 比较用对齐、共同尺度和差异编码；流程用方向、状态和交接；数据用单位、口径、来源和不确定性；概念用关系与层级；品牌可以用媒体、节奏和记忆锚点。
- 每页只设一个主焦点，但页面角色可以是问题、步骤、证据、体验、练习、过渡或情绪节拍。
- 普通页面负责铺垫和呼吸，关键页才提高比例、对比、空间变化或动效强度。
- 每份演示只选择一个全局画布模式：浅色或深色。封面、章节、证据页、媒体页和结尾不得以全页明暗反转制造节奏；卡片、图表、截图和媒体框可以局部对比，但不能演变成另一套页面主题。
- 若删除某个效果不影响理解、层级、因果或情绪，它就不应存在。
- 关键含义不能只存在于动画中；静态、打印与 `prefers-reduced-motion` 必须保留完整意思。

逐步揭示不是装饰，而是语义状态：先定义 hidden / active / past 或等价状态，再决定是否使用淡入、聚焦、空间连续性或无动画切换。

## 6. 结构化单一事实源

推荐让每个演示状态拥有如下最小数据：

```json
{
  "id": "stable-id",
  "role": "concept | evidence | demo | transition | exercise | close",
  "title": "观众在此刻需要处理的核心信息",
  "body": "内容或结构化节点",
  "notes": "仅 presenter 需要",
  "seconds": 0,
  "section": "main | appendix",
  "truth": "verified | proposed | simulated | unknown",
  "media": []
}
```

字段按场景裁剪。页面、目录、讲稿、累计时长和媒体引用应由同一数据源生成，避免 HTML、讲稿和验收页数各自漂移。Builder、最小重建命令和成品应同版本保存，并用 `deck-dependencies.json` 声明 authoring/runtime 文件、角色和 SHA256；若只能保留成品，明确标为 artifact-only。

## 7. Runtime 边界

最小配置声明比例、全局画布模式与四个可选 feature：

```json
{
  "version": 2,
  "aspect": "16:9",
  "background_mode": "light",
  "features": ["navigation", "presenter", "media", "dialog"]
}
```

`background_mode` 只允许 `light` 或 `dark`，并约束整套演示的全页画布。局部卡片、媒体与弹层可以使用对比表面，但不得借此形成交替的全页主题。version 1 仅作为旧产物兼容输入，不用于新生成。

- `navigation`：前后翻页、键盘、hash、进度。
- `presenter`：讲稿、计划时长、累计计时和演练视图。
- `media`：视频/音频生命周期、来源、失败兜底和 poster。
- `dialog`：确有分层阅读需要时的弹层与焦点管理。

数据图表和教学练习属于内容模式，不是 Runtime feature。动效是表现约束，`reduced-motion` 是所有演示的底线，不单独设 feature。

运行时只解决稳定问题：舞台缩放、状态切换、焦点与键盘、离页暂停、媒体失败、打印、可访问性与降级。它不能决定故事、行业对象、视觉隐喻和结尾。

## 8. 媒体门禁

媒体必须先说明角色：证明、操作演示、解释、情绪氛围或品牌资产。没有沟通收益就不加入。

生成式媒体按阶段通过：

1. 文字分镜与事实边界；
2. 关键帧/静帧，核对文字、界面、人物与构图；
3. 连续成片与声音；
4. 编码、音轨、时长、尺寸、poster、投影可读性和失败回退；
5. 最终映射到页面并做浏览器播放验收。

视频需要 poster；音频不需要。真实 UI、真实数据截图和事实证明不交给图像模型重绘。远程资产只有在明确依赖网络且目标环境验证过时才能保留，否则下载、缓存或打包为相对资源。

## 9. 质量门禁与身份绑定

通用门禁：

- 无未替换 placeholder、私密路径、密钥、内部聊天或提示词。
- 语义 DOM、语言、阅读顺序、对比度、键盘和 reduced-motion 可用。
- 内容顺序与目标一致，来源和限定靠近高风险主张。
- 目标视口无溢出、遮挡、过小字体和错误焦点。
- 最终文件使用相对资源，不依赖未经声明的 CDN。

条件门禁：

- `presenter` 才要求 notes 与页面一一对应。
- 使用视频才要求 poster；音频无此要求。
- `dialog` 才要求打开、关闭、Esc、焦点陷阱和返回焦点。
- 承诺离线双击时，实际验证 `file://`。
- 提供二维码或公网链接时，实际解码或访问并单独记录目标状态。
- 宣称自动路演时，完成一次连续全时长彩排；配置总时长不能替代。

每份验收回执必须记录：最终 `index.html` SHA256、页面数、media manifest SHA256（如有）、features、dependency manifest、`source_sha256`、variant 和 Builder revision（如有）。任何已声明的 authoring/runtime 文件变化都使旧回执失效。回执状态必须区分 `PASS_SOURCE_BOUND`、`PASS_RENDERED_ARTIFACT` 与 `PASS_LEGACY_ARTIFACT_ONLY`，不能把后两者简称为“源码已验证”。

## 10. 交付物矩阵

每种产物分别标记 `built / verified / unknown / not requested`：

| 产物 | 不能由什么替代 | 最小验收 |
|---|---|---|
| Live HTML | 静态截图 | 目标浏览器、视口、键盘、reduced-motion、启用功能 |
| PDF | 浏览器打印预览 | 实际导出后的分页、字体、裁切、静态最终态 |
| 视觉保真 PPTX | HTML/PDF | 实际打开、比例与视觉保真；可编辑性可能很低 |
| 可编辑 PPTX | 图片型 PPTX | 实际编辑关键文本/图形并检查转换损失 |
| 自动路演 | 分段点击测试 | 从头到尾连续播放一次 |
| MP4 | WebM/脚本/录制事件 | 最终文件编码、音轨、时长、首尾和播放 |
| 离线包 | 本机开发目录 | 干净环境解包、相对资源、无私密文件 |
| QR/公网 URL | 本地服务 | 真实目标访问、权限与移动端路径 |
| 正式提交/发布 | 可访问页面 | 平台成功页、回执或平台读取证据 |

## 11. 外部框架带来的边界

reveal.js、Slidev、Marp 和 impress.js 的共同启发是：

- 内容源与 HTML/CSS 壳分离，布局和主题是渲染层。
- 功能从简单内容开始按需启用；不要为框架能力反向制造内容。
- fragment/click 是语义状态，不是默认装饰。
- presenter、print/export、offline bundle 与 live web 是不同运行环境。
- 导出会丢失交互、字体、视频、canvas 或编辑性；必须单独验收。
- 动效无法弥补没有观点、结构或证据的内容。

不照搬具体 Markdown/Vue/SCSS 语法，也不把任何框架的插件集合变成 WowDeck 的全局要求。

本轮核对的一手实现与文档：

- [reveal.js](https://github.com/hakimel/reveal.js) 与其 [官方文档源](https://github.com/reveal/revealjs.com)
- [Slidev](https://github.com/slidevjs/slidev) 及 [导出边界](https://sli.dev/guide/exporting)
- [Marp](https://github.com/marp-team/marp) 与 [Marp CLI](https://github.com/marp-team/marp-cli)
- [Spectacle API](https://github.com/FormidableLabs/spectacle/blob/main/docs/api-reference.md)
- [impress.js 文档](https://github.com/impress/impress.js/blob/master/DOCUMENTATION.md)
- [WebSlides](https://github.com/webslides/WebSlides)

## 12. 最小前向验证

1. 同一事实源分别面向初学者与管理层，验证事实不变而内容逻辑有理由地不同。
2. 生成一个完整非提案演示，例如教学或研究；不得泄漏 Decision、Pilot、Capability 等旧案例结构。
3. 生成一个含 presenter 与 video 的决策型演示，确认旧能力可按需启用。
4. 验证 core 无 notes/media 可通过；presenter 缺 notes 失败；video 缺 poster 失败；audio 无 poster 可通过；placeholder 残留失败。
5. Chromium 覆盖标准视口、较小视口和 reduced-motion；只验收实际启用的 feature。

## 13. 仓库与发布边界

本仓库仅承载抽象后的 Skill、通用脚本、中性模板和合成测试：

- 成品演示、截图、音视频、客户或项目记录及反馈原话留在本机，不进入 GitHub，包括私有仓库。
- 安装目录只是验证后的同步副本。
- 从私人材料中提取经验只授权学习与抽象，不授权上传素材或可识别的案例叙述。
- 对任何具体私有材料的远端上传，必须另有针对该材料的明确授权。
- GitHub 推送不等于网站部署、Marketplace 发布或公开分享；这些动作需要各自明确授权与证据。
