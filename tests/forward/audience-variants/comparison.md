# 同一事实源 / 不同受众：对照与自审

## 测试结论

`beginner.md` 与 `management.md` 使用同一个冻结事实源 `fact-source.json`，均覆盖 F01–F10。两者的差异来自 Strategy Note 中的受众、使用情境和沟通工作，而不是改写事故。初级工程师路线以概念先修和迁移练习为中心；管理层路线以影响口径、恢复可信度和残余未知为中心。

## 有理差异

| 维度 | 初级工程师培训 | 管理层复盘 | 为什么合理 |
|---|---|---|---|
| **术语** | 首次出现时展开 p95、客户端超时、连接池、重试放大四个定义；标题用“怎样占满”“为什么变慢”等白话 | 使用“影响口径、直接放大路径、即时恢复”等复盘语言，只给必要限定 | 两者掌握的工程词汇不同；定义差异不改变事故事实 |
| **顺序** | 异常现象 -> 范围/影响 -> 术语先修 -> 根因链 -> 检测/处置 -> 恢复证据 -> 练习 | 状态/影响摘要 -> 影响边界 -> 根因与未知 -> 恢复时间线 -> 已知/未知 | 学习需要先修再推导；管理复盘需要先获得判断框架，再检查解释和证据 |
| **密度** | 7 页，一页一个认知动作；术语和因果分开 | 5 页，同页聚合状态、证据和限定语 | 初学者需要降低工作记忆负担；管理者需要在较短时间内看全判断边界 |
| **自解释程度** | 概念自解释更强，并保留讲师引导的静态练习 | 情境与结论自包含更强，来源状态和限定语留在正文以支持异步转发 | “会读懂术语”与“离开讲者也不误判状态”是两种不同的自解释需求 |
| **证据显著度** | 先解释概念和因果，再在每步旁标事实 ID；证据随学习过程逐步出现 | 数字、状态、时间范围、未知项从首页起即处于主视觉层级 | 培训优先形成模型；管理判断优先看证据边界，但两者均保留可追溯性 |
| **结尾** | 用事实分类与因果复述做迁移检查 | 用“已确认 / 仍未知”并列形成有界复盘状态 | 一个要证明理解迁移，一个要防止管理判断过度外推；都不强迫行动号召 |

## 路线差异不是换皮

```text
初级工程师：现象 -> 边界 -> 先修概念 -> 分步因果 -> 处置 -> 验证 -> 迁移练习
管理层：    状态+影响 -> 口径限定 -> 紧凑根因+未知 -> 恢复证据 -> 已知/未知收束
```

- 页数不同（7 对 5），节点拆合方式不同，入口和结尾行为不同。
- 初级工程师路线显式增加术语先修节点，但没有增加事故事实；管理层路线将相同事实聚合成判断单元。
- 两条路线共享事实图的因果边：F04 + F05 -> F06 -> F02/F03，以及 F07 -> F08 -> F09；不同的是穿越图的顺序与节点粒度。

## 模板泄漏检查

- 未把 **Decision / Pilot / Capability** 设为页面角色、标题或固定三段页序；这三个词仅在本检查项中用于说明禁用模板。
- 没有市场机会、解决方案、能力清单、试点、商业价值、投资回报、路线图或“批准下一步”等商业提案页。
- 培训结尾来自“能否迁移所学”的沟通工作；管理结尾来自“哪些结论能下、哪些不能下”的复盘工作，均由依赖图和受众转变推导。
- 页面数量不是预设模板：培训路线因四个先修概念和练习而拆为 7 页；管理路线因时间和异步扫描需求合并为 5 页。

## 前向质量自审

### Gate 1 — Strategy and content logic

- 两份文件都严格包含五项 Strategy Note、内容依赖图和逐页角色/标题路线。
- 受众、沟通工作、顺序、密度、自解释方式、证据显著度和结尾彼此一致。
- 可选运行时功能均为“无”，没有为了展示技能而引入 presenter、media、dialog 或固定互动。

### Gate 2 — Truth and evidence

- F01–F10 在两条路线中均有页面落点；所有数字、时间、因果、处置和未知项相同。
- 317 笔订单只描述为“事故窗口结束时仍未完成”，未改写为流失、取消或收入损失。
- 只把 F09 表述为即时恢复和直接放大路径解除，未写成长期风险全部关闭。
- 下游变慢原因和负载测试漏检原因保持未知；没有加入责任归属、金额或补救承诺。
- 虚构属性、内部分享边界和来源状态均可见。
