# 受众变体 A：初级工程师培训

> 测试边界：本文件只产出策略、内容依赖图和页面角色/标题路线，不生成 HTML。事故内容全部来自 [`fact-source.json`](fact-source.json)，且是明确标注的虚构测试情境。

## Strategy Note

### 1. Audience and context

- **主要受众**：入职不久、知道请求/服务基本概念，但尚不能独立分析级联延迟的初级工程师。
- **已有知识与阻力**：容易把延迟笼统归因为“服务器慢”，可能混淆 p95 与平均值，也可能把超时调大理解成单向度的“更稳”。
- **使用情境**：8 分钟中文内部培训，由讲师现场讲解；材料也应能在课后单独阅读。注意力按“一页一个认知动作”组织。
- **转发边界**：内部培训；第一页和结尾都保留“虚构测试情境”标记，避免截图脱离语境后被当作真实事故。

### 2. Desired shift and communication job

- **受众转变**：`只看到“接口变慢” -> 能用测量边界、触发条件、资源饱和、重试放大、恢复证据和未知项解释一次延迟事故`。
- **首要工作**：教会（teach）一条可复述的因果分析方法。
- **次要工作**：解释（explain）本例，并用一个静态练习（practice）检查是否会区分事实、因果和未知。
- 不承担事故问责、管理审批或商业说服任务。

### 3. Central question, route, and ending

- **中心问题**：为什么一次“把超时调大”的配置变化，会在下游间歇变慢时把结账 p95 从 480 毫秒推到 3.8 秒？
- **路线**：先从可感知的延迟跳变进入；再界定窗口和影响；补齐 p95、超时、连接池、重试四个先修概念；随后逐步拼出配置变化 + 下游变慢 -> 连接占用变长 -> 池饱和 -> 排队与重试放大 -> 延迟上升的链条；最后用回滚与 60 分钟观测区分“即时恢复已证实”和“仍未知”。
- **结尾**：不是行动号召，而是迁移练习——让学习者把同一组事实卡分成“观测、原因、处置、恢复证据、未知”，并用一句话重述链条。

### 4. Claim and evidence risk

本路线改变工程理解方式，因此所有数字、时间、因果和未知项都紧邻事实 ID；概念解释来自同一事实源的共享术语表。

| 高影响主张 | 来源与状态 | 允许表述 | 可见限定 |
|---|---|---|---|
| p95 从 480 ms 升至 3.8 s | F02，虚构事实 | 可说“延迟显著上升” | 明确 p95 不是平均值 |
| 影响为 2,146 次慢请求、317 笔窗口内未完成 | F03，虚构事实 | 只描述窗口内状态 | 不得写成 317 笔永久流失或收入损失 |
| 超时变长与下游变慢共同触发池饱和、排队和重试放大 | F04–F06，确认的根因链 | 按链条逐步说明 | 下游自身变慢原因仍未知（F10） |
| 直接放大路径已解除 | F08–F09，已实施且有 60 分钟观测 | 可说“即时恢复已验证” | 不得说长期风险全部关闭 |
| 事故仍有四类未知 | F10，未知项 | 原样列出 | 不推测答案 |

### 5. Delivery constraints and optional features

- **时长/画幅**：8 分钟，假定 16:9 大屏；本测试只验证内容设计，不实现画幅。
- **语言/分享**：中文，内部离线可读；核心术语首次出现时用白话解释，事实 ID 保留在页面证据条中。
- **规范源**：`fact-source.json` 是本测试的唯一事实源；本 Markdown 只是路线说明。
- **请求产物**：Strategy Note、依赖图、页面角色/标题路线；不请求 HTML、PDF、PPTX、MP4 或公开链接。
- **可选运行时功能**：无。静态练习只给出提示，不需要 `navigation`、`presenter`、`media` 或 `dialog`。
